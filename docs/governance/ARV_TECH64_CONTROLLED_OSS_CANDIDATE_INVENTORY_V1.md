# ARV Tech64 Controlled OSS Candidate Inventory v1

## 1. Purpose

This document establishes the controlled inventory boundary for a future ARV open-source candidate export.

It does not authorize publication, release, packaging or external distribution.

Its purpose is to identify the deliberately minimized public-candidate surface that may be prepared for independent review while preserving the protected commercial system behind the governance boundary.

## 2. Governing Doctrine

ARV preserves the foundational distinction:

**Proof != Authority**

Cryptographic evidence may establish integrity, traceability and provenance within the scope of captured evidence. It does not automatically establish absolute material truth, legal validity or judicial authority.

The canonical local kernel remains governed by the **LOCAL_L0** isolation doctrine.

## 3. Current Release Decision

Current controlled-export status:

**NO-GO**

The project may continue documentation, private validation, inventory preparation and protection-track execution.

No OSS repository, public package or release artifact is authorized by this document.

## 4. Controlled Public Candidate

A future OSS candidate must be an intentional, minimized and independently reviewed export.

The controlled public candidate may be prepared around narrowly scoped surfaces such as:

- public data schemas;
- portable verification interfaces;
- deterministic local verification logic;
- reproducible test vectors;
- interoperability examples;
- public-facing documentation;
- license notices;
- trademark exclusions;
- reproducible local smoke tests;
- neutral sample artifacts that do not expose protected implementation details.

A file does not become public merely because it exists in the private repository.

A component does not become public merely because it is technically separable.

## 5. Candidate Inventory Classes

### 5.1 Class A - Public-Candidate Review Surface

Potentially reviewable for a future minimized export:

- neutral specifications;
- public schemas;
- test vectors;
- narrowly scoped LOCAL_L0 verification logic;
- deterministic validation examples;
- reproducible smoke tests;

- sample integrations;

## 6. Repository Extraction Rule

Any future OSS preparation must use an explicit extraction procedure.

The public candidate must not be produced by copying the private repository wholesale.

The extraction procedure must:

- enumerate the exact approved files;
- preserve the protected-boundary exclusions;
- normalize UTF-8 without BOM;
- generate a SHA-256 manifest;
- run reproducible build and smoke checks;
- verify absence of secrets and productive credentials;
- confirm license compatibility;
- confirm trademark and seal exclusions;
- confirm absence of private implementation leakage;
- record an explicit signed GO / NO-GO decision.

## 7. Mandatory Pre-Publication Controls

Before any future publication decision, the candidate export must pass:

- exact repository inventory;
- exact file allowlist review;
- explicit public-versus-protected classification;
- clean worktree verification;
- reproducible build;
- reproducible smoke tests;
- UTF-8 without BOM normalization;
- SHA-256 manifest generation;
- secret scanning;
- dependency review;
- license review;
- contributor-governance review;
- trademark review;
- certification-seal exclusion review;
- private implementation leakage review;
- signed GO / NO-GO decision.

## 8. Audit Principle

ARV will not publish its private repository by inertia.

Any future public export must be deliberately minimized, separately reviewed and independently auditable.

The protected commercial system remains isolated behind the governance boundary.

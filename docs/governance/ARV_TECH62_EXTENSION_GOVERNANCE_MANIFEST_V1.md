# ARV Tech62 Extension Governance Manifest v1

## 1. Doctrina Fundamental
La premisa absoluta de este proyecto es: **Proof ≠ Authority**.

ARV demuestra integridad, trazabilidad y procedencia (Proof) de un archivo o evento en el tiempo mediante reglas matemáticas verificables.

ARV no declara por sí mismo la verdad material absoluta de un hecho, no sustituye el contexto jurídico y no reemplaza una determinación judicial.

## 2. Aislamiento LOCAL_L0
El kernel criptográfico de ARV opera bajo la doctrina LOCAL_L0.

LOCAL_L0 funciona de forma autónoma, offline y air-gapped.

RFC 3161, TSA, HSM, KMS, PostgreSQL, billeteras y blockchains NO son dependencias activas del kernel.

Su incorporación futura se realizará exclusivamente mediante adaptadores declarados, sin contaminar el núcleo local.

## 3. Modelo Comercial y Estrategia de Apertura
ARV emplea una estrategia open-core segmentada por superficies.

El gancho comercial primordial es **ARV Snap**.

El núcleo mínimo de verificación local podrá exponerse para adopción masiva e interoperabilidad.

La emisión oficial, ProofOps, los empaquetados de evidencia, el Gateway administrado, la API empresarial, la instrumentación comercial y el Baúl de pruebas permanecen cerrados y propietarios.

Los siguientes componentes NO forman parte del OSS mínimo:

- ARV Snap official issuance;
- ProofOps;
- Baúl de pruebas;
- Evidence Certificate;
- Bundle Evidence Package;
- Dispute Pack;
- Policy Engine;
- Dispute Logic;
- API empresarial;
- Gateway administrado;
- adaptadores productivos;
- telemetría;
- claves;
- secretos.

## 4. Barrera Jurídica Mínima Pre-OSS
Antes del lanzamiento público del OSS mínimo deberán cumplirse estas condiciones:

1. El nombre comercial `REALITY VALIDATION AUTHORITY ARV` permanece registrado ante ONAPI.
2. La solicitud de marca denominativa deberá presentarse ante ONAPI con descripción exacta de productos y servicios y clases candidatas 9 y 42 sujetas a revisión final.
3. El snapshot privado pre-OSS de LOCAL_L0 deberá depositarse ante ONDA como programa de computadora y preservarse junto con hashes SHA-256, commit y comprobante.
4. El emblema institucional canónico se registrará después de congelar su diseño definitivo.
5. Los sellos de certificación se reservarán para una fase posterior, una vez exista reglamento de uso y revisión jurídica.
6. La constitución de la SRL continuará en paralelo para consolidar contratos, cobros, licencias comerciales y titularidad derivada.
7. No existe un gate activo de patentabilidad para el lanzamiento inicial.

## 5. Regla de Lanzamiento
ARV publicará capacidad mínima de verificación.

ARV no publicará capacidad de emisión oficial, orquestación comercial ni captura de valor.
